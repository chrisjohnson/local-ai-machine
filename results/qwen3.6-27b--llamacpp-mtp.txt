Step 3: Root-cause confirmation — is this a flag issue or a file issue?
============================================================

Checked the source HF repo's file listing (unsloth/Qwen3.6-27B-GGUF, the repo our
local file came from) via the HF API — no filename in that repo mentions "mtp" at
all (BF16, IQ4_NL/XS, Q3/Q4/Q5/Q6/Q8_0, UD-* variants — none carry MTP head
tensors).

Searched HF for other repos and found a DISTINCT, separate repo from the same
publisher: `unsloth/Qwen3.6-27B-MTP-GGUF` — confirms unsloth ships MTP-head-bearing
GGUFs as an entirely separate repo/download, not as extra files alongside the
plain non-MTP quants we already have. Root cause confirmed: this is a genuine
missing-artifact problem, not a wrong-flag or wrong-config problem. The mechanism
(--spec-type draft-mtp) is real and works as documented upstream; our specific
locally-downloaded file simply predates/excludes the MTP head tensors.

Per the task's explicit instruction not to download anything new, no attempt was
made to pull unsloth/Qwen3.6-27B-MTP-GGUF or any other MTP-tagged repo. This
remains an open, actionable follow-up (a real MTP-bearing file would need to be
downloaded — a new-model-download decision, not something to do autonomously per
this project's standing download check-in rule).
