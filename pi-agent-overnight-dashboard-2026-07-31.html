M-039 — Claude bridge Done

Built, verified, both paths working

pi-claude-bridge lets Claude models (your own Pro subscription, not metered API billing) be selected inside pi like any other model, plus an "AskClaude" delegation tool from other models.

  • claude CLI pinned and installed in the pi-web image; pi-claude-bridge installed and registered; claude-bridge.json seeded with provider.plan: "pro" (never "max").
  • IS_SANDBOX=1 enabled after you were walked through the actual tradeoff (it doesn't grant new tool access beyond what this container already gives any selected model — it only lets the claude subprocess start at all as root). Deployed and confirmed: the original "--dangerously-skip-permissions cannot be used with root" error is gone.
  • Auth is via CLAUDE_CODE_OAUTH_TOKEN (see resolution below) — no credential file staged in the container at all anymore.
Now fully resolved

The 401 OAuth access token has been revoked error turned out not to be a stale or corrupted copy — hash-compared the credential file against your Mac's and they were byte-identical. Root-caused it properly rather than just re-copying and hoping: wrote a minimal script hitting the Claude Agent SDK directly, reproduced the exact same 401 locally on your Mac by running it against a fresh, isolated $HOME. That proved it wasn't box-specific, container- specific, or a dead token — the Agent SDK's own "fetch OAuth profile" step is stricter than the plain claude CLI's auth path, and rejects a bare copied credentials file even though the identical file authenticates fine through claude -p. Ruled out along the way: account- level SDK restriction, IS_SANDBOX=1 itself, a missing oauthAccount field in ~/.claude.json, and pure macOS Keychain access (the isolated local test ran as the same logged-in user with full Keychain access and still failed).

The actual fix: claude setup-token, Anthropic's own documented mechanism for headless/ CI-safe, subscription-backed auth. Produces a 1-year sk-ant-oat01-... token, read via the CLAUDE_CODE_OAUTH_TOKEN env var — no file staging or ownership-fixing needed at all, simpler than the credential-copy approach it replaced. Set directly in docker/docker-compose.yml's pi-web environment; the old credential-file volume mount was removed as obsolete.

Verified independently, both paths: the provider path (selecting claude-bridge/claude-sonnet-5 as the active model) returned a correct BRIDGE-OK test response, and the AskClaude delegation tool (calling Claude from another model) independently returned ASKCLAUDE-OK. Both real, live completions through your own Claude Pro subscription, not metered API billing.

M-041 — Watchdog/judge pattern design Done

Pure research and design — confirmed the real, available mechanism for a fast model to watch another session for drift/loops, grounded directly in pi's own extension API (not the fabricated "stagnation heuristics" claims another agent had asserted earlier, which didn't hold up under direct source inspection).

  • Real levers: a tool_call hook can block a call outright with a corrective reason, or a steer message can redirect mid-turn.
  • Real limitation stated plainly: extensions cannot force a session to stop or veto continuing to the next turn. A genuinely hard stop would need building directly on pi-agent-core's own Agent class instead of pi's extension system — bigger, separate undertaking.
  • Design generalizes: the same "rolling window → ask the judge → block or steer" shape is meant to work for future guardrails beyond the one M-042 will implement first.

M-043 — litellm roles moved to DB-only, API-managed Done

Not one of the original six — surfaced while adding the vision role, and became a real architecture fix at your direction. The previous design committed role values to docker/litellm/config.yaml, edited in place by set-role.sh via sed. The first time a genuinely new role needed both a new committed block and a live runtime flip in one session, that collided as a real git conflict on the box.

Your explicit direction: terraform's lifecycle {'{'} ignore_changes {'}'} as the reference model. Now:

  • store_model_in_db: true enabled (litellm already had a Postgres DB wired up — no new infra).
  • coder/judge/vision removed from the static YAML entirely — they live only in litellm's own database, managed via its real Model Management API (confirmed against our own running instance's OpenAPI schema, since the public docs page had moved/404'd).
  • scripts/litellm-bootstrap.sh (new) seeds each role once with a deliberately non-functional stub (openai/UNCONFIGURED-run-set-role.sh) if it doesn't exist — your explicit refinement, so a future session can never mistake a stub for a stale- but-plausible real value.
  • scripts/set-role.sh rewritten to call the API instead of editing a file — changing a role's live model is now a pure API call. No git conflict is possible on this by construction. No litellm restart is needed either (a real improvement, confirmed empirically — the proxy's uptime stayed constant across all three role updates during deploy).

Also fixed two real, unrelated bugs found in the old set-role.sh while rewriting it: creating a genuinely new role silently did nothing (a non-matching sed range is a no-op, but the script printed success regardless), and a dead code path used a literal string instead of a shell variable, so it could never have matched anything for any role name.

What was done: all ~13 accidentally-started containers stopped immediately, by name. coder restarted, scoped correctly.
