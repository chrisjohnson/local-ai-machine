# M-054.1 — Fix oh-my-pi Docker build blockers and deploy to box

## Context
<!-- why this card exists: root cause, links to runbooks/PRs/related cards -->

M-054 (done 7874d47) drafted the omp litellm-seed image but the first build
attempt on the box failed with two blockers, reported by Chris 2026-08-01:

1. `Blocked 2 postinstalls. Run \`bun pm -g untrusted\` for details.` — bun
   blocks untrusted lifecycle scripts by default. The two blocked packages
   (verified in a throwaway node:22-bookworm-slim repro): `onnxruntime-node`
   ([postinstall] node ./script/install — downloads the native .node binary,
   hard runtime requirement for embeddings/memory) and `protobufjs`
   ([postinstall] node scripts/postinstall — bundling step).
2. `chmod: changing permissions of '/usr/local/bin/docker-entrypoint.sh':
   Operation not permitted` — BuildKit COPY'd files are root-owned even when
   the active USER is non-root; chmod after `USER omp` failed with EPERM.

Deployment also revealed a third latent bug (found in local smoke test): the
seeded entrypoint replaces upstream's `ENTRYPOINT ["omp"]` but CMD stayed
`["cli"]` — `cli` is a subcommand of the omp binary, not a PATH executable, so
`exec cli` failed. omp must be dispatched explicitly (`omp cli`).

## Plan
